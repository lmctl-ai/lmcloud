# 18 — `lmcloud` Userpool Conformance Suite & Simulator Enhancements (Slice 6)

## 1. Runner Usage & Gates

```bash
LMSCRIPT_BIN=/home/ubuntu/lmctl-mono/lmscript/bin/lmscript ./tests/run-conformance.sh --check userpool
./tests/run-conformance.sh /path/to/lmaws http://127.0.0.1:4566 userpool
```

- Every scenario carries `# Requires: userpool`; `tests/capabilities.conf` marks **all hosts + reference host `pending(...)`** (adapter/ epic-specific reasons) until the adapter lands AND passes this suite.
- `userpool` is excluded from the `--live` profile (runner slice-dir rule); design 17 §1.2 additionally refuses mutations on live routes until native certification.
- Static gates: outer `--check` + embedded `_lmcode_` compile gate (negative control retained).
- Naming: pools `lmu<NN><run_id>` + letter suffix (`^[a-z][a-z0-9]{2,31}$`); users `user<NN>_<run_id>_<suffix>`; groups `grp<NN>_<run_id>_<suffix>` (alnum+underscore rules); attribute names ≤20 chars (Cognito custom-schema floor, design 17 §2.2).
- Aggregate assertions (`userpool_list`, `group_list`, `user_groups`, `user_list` walks) use bounded restart-per-poll loops (≤12), uniqueness asserted *as items arrive*, token invariant checked per page (design 17 §2.5).
- **Enforcement fixtures (scenario 11):** AWS-only today; requires `LMCLOUD_ENFORCE_DENIED_AWS_*`; the mode probe demands exact `UNAUTHENTICATED` from bogus credentials (any other outcome fails, never silently classifies); **`LMCLOUD_EXPECT_ENFORCE=1` turns an open-mode answer into a failure** (an accepted bogus credential can never masquerade as a benign open run when enforcement was expected); Pass 2 seeds with the privileged identity (seed success asserted) before restricted legs; cleanup runs with the restored seed identity *before* final assertions.
- **Secrets:** conformance scenarios never echo passwords or tokens; scenario 05 asserts identical generic messages for wrong-password and missing-user and no password echo; scenario 07 asserts error messages contain neither the original nor the tampered token, plus `alg:none` rejection and cross-pool rejection.

## 3. Simulator Enhancements (evidence-backed; upstream file:line references)

1. **A-UP1 `awssim`** — certify the in-process Cognito IDP subset: `CreateUserPool` + per-pool app client (`CreateUserPoolClient`, **no client secret**, `ALLOW_ADMIN_USER_PASSWORD_AUTH`), `AdminCreateUser` with `MessageAction=SUPPRESS`, `AdminSetUserPassword` (Permanent), `AdminGetUser/DeleteUser/SetUserPassword...`, `ListUsers` (`PaginationToken`), groups ops, `AdminInitiateAuth` with **`ADMIN_USER_PASSWORD_AUTH`** (not the public `InitiateAuth` path, and not `USER_PASSWORD_AUTH` on the Admin API which is invalid), token verify via pool-bound JWKS/discovery; extend `AuthFilter.SUPPORTED` with a `cognito-idp` set + tests. Note: upstream `.../services/cognito/CognitoService.java:5081-5082` stores `passwordHash` as plain SHA-256 — acceptable only for synthetic test fixtures (design 17 §2.4).
2. **AZ-UP1 `azuresim`** — evidence from source reads: upstream floci-az HAS Graph membership endpoints + a directory store (`.../graph/GraphServiceHandler.java:24-38,84-101`) but `.../entra/PasswordGrant.java:8-9` accepts a password grant **without checking the password**. Epic: validated directory CRUD + password-checked sign-in + tenant-scoped issuance + enforce routes.
3. **G-UP1 `gcpsim`** — **material gaps, not mere certification:** upstream `.../services/firebaseauth/FirebaseJwt.java:11-22` mints `alg:none` tokens with an empty signature; `.../FirebaseAuthService.java:34-38` keeps a `fakeHash` dev fixture. Epic: RS256 signing + pool/tenant-bound JWKS/discovery + Identity-Platform tenant units (pool isolation) + `PermissionFilter` mapping. **Until G-UP1 lands, the GCP leg refuses token verification (`UNSUPPORTED_MAPPING`) rather than accepting unsigned emulator semantics** (design 17 §2.6). Groups on GCP: host-managed membership records on the sim route; refused natively (design 17 §4.1/D4).
4. **O-UP1 `ocisim`** — upstream floci-oci lists Identity Domains as not-implemented (README); the absence was probed once earlier (404s) but is not runtime-certified in this round — marked pending `oci-identity-domains-epic`.

## 4. Implementation Acceptance Criteria (before any capability flips to supported)

1. **Pool isolation:** same username in two pools with distinct passwords works with no cross-access; recreated pool never accepts a prior-incarnation token (issuer/keys rotate + fresh catalog record with fresh session generations); physical UID ↔ username + reverse-lookup maps + owner/scope metadata journaled; exact delete scope.
2. **Token security fixtures (single exact policy: strict expiry, zero expiry leeway — valid iff `now < exp`, integer epoch seconds, `exp == now` invalid; issuance leeway `iat <= now + 60` only; `expires_in` on verify = `exp - now` ≥ 1; revocation via the journaled digest→binding registry, design 17 §2.6):** injected-clock boundary (`exp == now` reject, `exp == now + 1` accept), future-`iat` (>+60 s) reject, same-second revoke cases (issue + disable / password-set / delete all inside one epoch second — bumped generation revokes; same-second new sign-in binds the new generation and works), key rotation with bounded JWKS cache (≤256 KiB / ≤16 keys / ≤1 h), duplicate-claim reject, oversize token (>8192 B) reject, disallowed-algorithm reject with an otherwise-valid fixture (valid pool/client/tenant/subject claims, only the algorithm changed), wrong project/client/tenant binding reject, never-issued/fabricated/foreign-pool digest lookup reject, post-delete token always invalid, >128 live bindings evicts oldest deterministically, crash-reopen registry reconstructed from journal.
3. **Redaction canaries:** escaped-representation secrets, <8-byte invalid inputs, provider-echoed secrets, >256-registration sequences, failure-path and abort-path errors — none contain the secret.
4. **Lifecycle/crash:** crash/reopen mid-campaign replay, failed-journal no-dispatch, exhausted-work cleanup with reserved headroom, foreign-child preservation blocking teardown, quarantine of pool names through terminal deletion (no same-name reuse), late-operation fencing (async op observed after delete → quarantined, never re-adopted).
5. **Pagination authority:** page tokens are HMAC-signed and bound to `(endpoint, caller scope fingerprint, pool physical id + incarnation, ordering, max_items, index cursor)` with 300 s expiry; keys persist as `0600` run-state files (never in journals) and rotate on reopen; tokens across pools/incarnations/**callers**/endpoints rejected; malformed/oversize/expired tokens rejected; empty pages with continuation followed; no-progress stall → INTERNAL; **global ordering proven** from out-of-order native pages (host builds a projected username/UID index snapshot ≤2000 entries and sorts that, then joins bounded page profiles — never a sorted native partial window); >2000th user refused pre-flight; large-profile pools stay within the 1 MiB page-join budget.
6. **Dry/live:** dry-mode `user_sign_in`/`user_verify_token` fail closed with zero SDK calls; live routes refuse **all** userpool operations (including sign-in/verify) until certified — independent of runner exclusion.
7. **Per-attempt admission:** catalog/JWKS/discovery/client-create/user/group/membership/page/poll/retry/cleanup calls are each metered with durable attempt IDs; sign-in and non-idempotent provisioning are never blindly retried.
