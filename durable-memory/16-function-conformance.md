# 16 — `lmcloud` Function Conformance Suite & Simulator Enhancements (Slice 6)

## 1. Conformance Runner Usage

[`tests/run-conformance.sh`](../tests/run-conformance.sh) accepts `object-storage`, `queue`, `cost-perf`, `tables`, `permissions`, `function`, or `all` (default `all`):

```bash
# Static compile/typecheck against schema/lmcloud.dsl.json (outer .lms + embedded _lmcode_ blocks):
LMSCRIPT_BIN=/home/ubuntu/lmctl-mono/lmscript/bin/lmscript ./tests/run-conformance.sh --check all
LMSCRIPT_BIN=/home/ubuntu/lmctl-mono/lmscript/bin/lmscript ./tests/run-conformance.sh --check function
LMSCRIPT_BIN=/home/ubuntu/lmctl-mono/lmscript/bin/lmscript ./tests/run-conformance.sh --live --check all

# Execute against each provider + simulator once Go Functions adapters and sim enhancements land:
./tests/run-conformance.sh /path/to/lmaws   http://127.0.0.1:4566 function
./tests/run-conformance.sh /path/to/lmazure http://127.0.0.1:4577 function
./tests/run-conformance.sh /path/to/lmgcp   http://127.0.0.1:4588 function
./tests/run-conformance.sh /path/to/lmoci   http://127.0.0.1:4599 function
```

### Naming, Live-Profile Exclusion & Capability-Skip Rules
- Logical function names are `lmf<NN><run_id><suffix>` matching the portable alphanumeric rule `^[a-z][a-z0-9]{2,31}$` ([`15-function-design.md` §4.1](15-function-design.md)). Every scenario embeds a per-run `run_id` (`ARGV[2]`). Physical provider targets use incarnation-scoped names `lmfn-{name}-{inc8}` (§3.1).
- **Live-profile exclusion:** `--live` (`is_live_excluded_scenario` in `tests/run-conformance.sh`) explicitly excludes `function/` alongside `cost-perf/`, `tables/`, and `permissions/`. Running `./tests/run-conformance.sh --live --check all` compiles only the 23 live-eligible `object-storage` and `queue` scenarios; targeting `--live --check function` exits with code `2`.
- **Capability skip mechanism (`tests/capabilities.conf`):**
  1. Every scenario in `tests/conformance/function/` carries `# Requires: function` on line 1.
  2. Until the Go `Functions` adapter (`hostkit.Functions` + `cloudhost` bindings + `fakeadapter` + provider adapters), the §4 implementation acceptance tests (`G1`–`G8`), and simulator enhancements (`A-FN1..3`, `AZ-FN1..2`, `G-FN1..2`, `O-FN1`) are implemented and verified, all five hosts (`lmaws`, `lmazure`, `lmgcp`, `lmoci`, `lmcloud-ref`) remain marked `pending(go-function-adapter;...)` in [`tests/capabilities.conf`](../tests/capabilities.conf).
  3. The runner reports `ok N - function/NN-... # SKIP <reason>` in TAP output and counts each as `skip` (never `pass`).

## 4. Mandatory Implementation Acceptance Gates (Before Removing `pending(...)` in `capabilities.conf`)

Compiling the 13 `.lms` conformance scripts (`--check`) validates schema and script syntax only. Before flipping **any** host's `function` entry from `pending(...)` to `supported` in [`tests/capabilities.conf`](../tests/capabilities.conf), the Go implementation and `scripts/test-hostkit.sh` MUST pass all of the following deterministic acceptance tests:

1. **G1 — Malicious Archive & Zip-Bomb Rejection:** Unit tests feeding `CreateFunction`/`UpdateFunction` archives with `> 16 MiB` compressed size, `> 64 MiB` uncompressed expansion (zip bomb), `> 256` entries, `../` path traversal, absolute paths, symlinks/device nodes, and case-colliding duplicate entries; all must fail with `INVALID_ARGUMENT` before writing or executing any file.
2. **G2 — OS Namespace Isolation Canary (`/proc`, Host Filesystem, Loopback Network, & `os.environ`):** Launch the worker with a canary variable in its own process environment (`WORKER_CANARY=secret`), a `0600` canary file in the host user's `/tmp` outside the bundle, and a local loopback listener; invoke a handler that attempts to (a) read `os.environ`, (b) scan `/proc/[0-9]*/environ` for `WORKER_CANARY`, (c) open the `0600` host file path, and (d) connect to `127.0.0.1:<sim_port>`. Verify all four probes fail inside the `CLONE_NEWUSER | CLONE_NEWPID | CLONE_NEWNS | CLONE_NEWNET` sandbox, and verify that if namespace creation is disabled, `function_invoke` fails closed with `ErrorCode.INTERNAL`. Also verify `ErrorState.AddRedaction` scrubs configured `cfg.env` values from `CloudError.message()` and abort output while preserving `result.logs()` / `result.payload()`.
3. **G3 — PID-Namespace Session-Escaping Descendant Reaping & Memory OOM Enforcement:** Invoke a handler that spawns a grandchild calling `os.setsid()` and sleeping past `timeout_seconds`, verifying the PID-namespace teardown kills the `setsid()` grandchild (`ESRCH`) before `function_invoke` returns `function_error() == "Timeout"`; invoke a handler that allocates beyond `memory_mb` (`128 MiB`), verifying it terminates with `is_error() == true` and `function_error() == "Unhandled"`.
4. **G4 — Cross-Process Stale-Quote / Alias-Retarget Cost Admission, Malformed Provider Billing, & Lost-Reply Retention:** Child invocation A observes `$LATEST` (or alias `"prod"`) at `1 s / 128 MiB`; child invocation B updates `$LATEST` (or retargets `"prod"`) to `230 s / 2048 MiB`; child A then calls `function_invoke` under a work sub-cap that admits `1 s / 128 MiB` (`1,100` units) but not `230 s / 2048 MiB` (`3,680,100` units) — verify child A's catalog resolution rejects the invoke pre-flight with `COST_CAP_EXCEEDED` (`http_status() == 0`). Also inject (a) a mid-flight connection drop after `function_invoke` request dispatch and (b) a malformed/out-of-range `provider_billed_ms` (`-5` or `999999`), verifying both retain the full worst-case duration reservation (`timeout_seconds * 1000` ms) with zero replay.
5. **G5 — Repeated Update Synchronous GC, Interrupted Update Drain, & Resumed Child Sweep:** (a) Perform 50 consecutive `function_update` calls with distinct code without publishing versions and verify synchronous GC keeps retained staged bundles in `lmcloudfn-pkgs` `<= 3`; (b) inject a failure mid-`function_update` after staging a candidate bundle, then narrow `set_cost_cap_usd(estimated_cost())` and run `function_delete` / resumed child `Sweep` across a function with 16 versions + 16 aliases + 1 unreferenced candidate, verifying all artifacts are deleted within the `$0.00079000` locked cleanup reserve.
6. **G6 — Delayed In-Flight Native Write Across Lease Expiry, Delete, & Recreate:** Pause a writer's admitted native control-plane request (`UpdateFunctionConfiguration` / `PutFunctionConcurrency`) in an HTTP interceptor, allow the lease to expire, run `function_delete` + `function_create` (creating a new incarnation `lmfn-{name}-{new_inc8}`), and then release the paused request; verify the delayed request targets only the old incarnation `lmfn-{name}-{old_inc8}` (`404`) and leaves the new incarnation untouched.
7. **G7 — Simultaneous Multi-Call Concurrency Cap & Killed-Caller Slot Retention:** With `concurrency = 2`, launch 3 barrier-synchronized concurrent `function_invoke` calls across `$LATEST`, version `"1"`, and alias `"prod"`; verify 2 succeed (`200`) and the 3rd fails with `ErrorCode.PRECONDITION_FAILED` (`http_status() == 429`). Then kill one in-flight caller process while its 2-second remote handler is still running, immediately issue another `function_invoke`, and verify the slot remains held until `expires_at_unix_ms` (`429` while the orphaned execution is still active).
8. **G8 — Instrumented Dry-Run Zero-Execution & Overlay Coherence Proof:** Execute the extracted inner `_lmcode_` blocks of all 13 function scenarios (and a dedicated dry-overlay lifecycle script) under `lmscript --dry-run` against an instrumented adapter, verifying zero handler processes are spawned, zero network requests are issued, and `function_create` -> `function_exists` -> `function_get` -> `function_publish_version` -> `function_alias_set` -> `function_invoke` -> `function_delete` transitions are coherent in the dry overlay. (Note: outer `.lms` assertions that inspect runtime-computed handler output such as `"42"` or raised errors apply to live/sim execution, whereas G8 asserts zero side effects and dry-overlay state coherence.)
