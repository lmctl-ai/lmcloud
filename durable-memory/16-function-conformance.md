# 16 — `lmcloud` Function Conformance Suite & Simulator Enhancements (Slice 6)

## 1. Conformance Runner Usage

[`tests/run-conformance.sh`](../tests/run-conformance.sh) accepts `object-storage`, `queue`, `cost-perf`, `tables`, `function`, or `all` (default `all`):

```bash
# Static compile/typecheck against schema/lmcloud.dsl.json (outer .lms + embedded _lmcode_ blocks):
LMSCRIPT_BIN=/home/ubuntu/lmctl-mono/lmscript/bin/lmscript ./tests/run-conformance.sh --check all
LMSCRIPT_BIN=/home/ubuntu/lmctl-mono/lmscript/bin/lmscript ./tests/run-conformance.sh --check function
LMSCRIPT_BIN=/home/ubuntu/lmctl-mono/lmscript/bin/lmscript ./tests/run-conformance.sh --live --check all

# Execute against each provider + simulator once Go Functions adapters and sim enhancements land:
./tests/run-conformance.sh /path/to/lmaws   http://127.0.0.1:4566 function
./tests/run-conformance.sh /path/to/lmazure http://127.0.0.1:4577 function
./tests/run-conformance.sh /path/to/lmgcp   http://127.0.0.1:4588 function
./tests/run-conformance.sh /path/to/lmoci   http://127.0.0.1:4599 function
```

### Naming, Live-Profile Exclusion & Capability-Skip Rules
- Function names are `lmf<NN><run_id><suffix>` matching the portable alphanumeric rule `^[a-z][a-z0-9]{2,31}$` ([`15-function-design.md` §4.1](15-function-design.md)). Every scenario embeds a per-run `run_id` (`ARGV[2]`).
- **Live-profile exclusion:** `--live` (`is_live_excluded_scenario` in `tests/run-conformance.sh`) explicitly excludes `function/` alongside `cost-perf/` and `tables/`. Running `./tests/run-conformance.sh --live --check all` compiles only the 23 live-eligible `object-storage` and `queue` scenarios; targeting `--live --check function` exits with code `2`.
- **Capability skip mechanism (`tests/capabilities.conf`):**
  1. Every scenario in `tests/conformance/function/` carries `# Requires: function` on line 1.
  2. Until the Go `Functions` adapter (`hostkit.Functions` + `cloudhost` bindings + `fakeadapter` + provider adapters), the §4 implementation acceptance tests, and simulator enhancements (`A-FN1..3`, `AZ-FN1..2`, `G-FN1..2`, `O-FN1`) are implemented and verified, all five hosts (`lmaws`, `lmazure`, `lmgcp`, `lmoci`, `lmcloud-ref`) remain marked `pending(go-function-adapter;...)` in [`tests/capabilities.conf`](../tests/capabilities.conf).
  3. The runner reports `ok N - function/NN-... # SKIP <reason>` in TAP output and counts each as `skip` (never `pass`).

## 4. Mandatory Implementation Acceptance Gates (Before Removing `pending(...)` in `capabilities.conf`)

Compiling the 13 `.lms` conformance scripts (`--check`) validates schema and script syntax only. Before flipping **any** host's `function` entry from `pending(...)` to `supported` in [`tests/capabilities.conf`](../tests/capabilities.conf), the Go implementation and `scripts/test-hostkit.sh` MUST pass all of the following deterministic acceptance tests:

1. **G1 — Malicious Archive & Zip-Bomb Rejection:** Unit tests feeding `CreateFunction`/`UpdateFunction` archives with `> 16 MiB` compressed size, `> 64 MiB` uncompressed expansion (zip bomb), `> 256` entries, `../` path traversal, absolute paths, symlinks/device nodes, and case-colliding duplicate entries; all must fail with `INVALID_ARGUMENT` before writing or executing any file.
2. **G2 — Sandbox Credential Scrubbing & Secret Redaction Canary:** Invoke a handler with canary secrets (`AWS_SECRET_ACCESS_KEY=canary-secret`, `LMAWS_SIM_SECRET_ACCESS_KEY=canary-secret`, `LMOCI_SIM_PRIVATE_KEY_PATH=/secret`) set in the host/simulator process environment and verify `os.environ` inside the handler contains zero host/simulator secrets; trigger a forced provider error on a function with `set_env("API_SECRET", "top-secret-value")` and verify `last_error().message()` and abort output redact `"top-secret-value"`.
3. **G3 — Subprocess Process-Group Reaping & Memory OOM Enforcement:** Invoke a handler that spawns a background child subprocess and sleeps past `timeout_seconds`, verifying the child PID is killed (`ESRCH`) before `function_invoke` returns `function_error() == "Timeout"`; invoke a handler that allocates beyond `memory_mb` (`128 MiB`), verifying it terminates with `is_error() == true` and `function_error() == "Unhandled"`.
4. **G4 — Cross-Process Stale-Quote / Alias-Retarget Cost Admission & Lost-Reply Retention:** Child invocation A observes `$LATEST` (or alias `"prod"`) at `1 s / 128 MiB`; child invocation B updates `$LATEST` (or retargets `"prod"`) to `230 s / 2048 MiB`; child A then calls `function_invoke` under a work sub-cap that admits `1 s / 128 MiB` (`1,100` units) but not `230 s / 2048 MiB` (`3,680,100` units) — verify child A's catalog resolution rejects the invoke pre-flight with `COST_CAP_EXCEEDED` (`http_status() == 0`). Also inject a mid-flight connection drop after `function_invoke` request dispatch and verify the full worst-case reservation remains committed in the journal (`no-replay` + zero refund).
5. **G5 — Incremental Child Cleanup Reserves & Resumed Journal Sweep:** Create a function, publish 16 versions and 16 aliases, narrow `set_cost_cap_usd(estimated_cost())`, verify ordinary work (`function_invoke`, `function_update`) fails with `COST_CAP_EXCEEDED` while a resumed child process calling `function_delete` (or `Sweep`) deletes all 16 aliases, 16 versions, staged bundles, native function, and catalog tombstone within the locked cleanup reserve.
6. **G6 — Multi-Writer Catalog Lease & Delete/Recreate Incarnation Fencing:** Simulate concurrent `function_update` writers and an interleaved `function_delete` + `function_create` (new `incarnation_id`), verifying stale writers are fenced by `(incarnation_id, op_gen)` and cannot overwrite the new incarnation or resurrect a `"deleting"` function.
7. **G7 — Simultaneous Multi-Call Concurrency Cap Enforcement:** With `concurrency = 2`, launch 3 Barrier-synchronized concurrent `function_invoke` calls across goroutines/processes; verify 2 succeed (`200`) and the 3rd fails with `ErrorCode.PRECONDITION_FAILED` (`http_status() == 429`).
8. **G8 — Dry-Run Zero-Execution & Zero-Mutator Proof:** Run all 13 `tests/conformance/function/*.lms` programs under `lmscript --dry-run` against an instrumented adapter, verifying zero handler subprocesses are spawned and zero mutating HTTP calls are issued.
