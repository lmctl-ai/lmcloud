# 03 — Object Storage Conformance Scenarios (`lmcloud`)

Each conformance scenario below is an `lmscript` program (`load_schema` / `_lmcode_` / `run_lmcode`) that must pass unchanged against all four host+simulator pairs (`lmaws`+`awssim:4566`, `lmazure`+`azuresim:4577`, `lmgcp`+`gcpsim:4588`, `lmoci`+`ocisim:4599`):

1. **`01-bucket-lifecycle`** — Creating a new bucket returns `true`, makes `bucket_exists` return `true` and includes the bucket in `bucket_list` in sorted order, and deleting the empty bucket returns `true` and makes `bucket_exists` return `false`.
2. **`02-bucket-idempotency-and-nonempty-guard`** — Calling `bucket_create` on an existing caller-owned bucket returns `false` without error, calling `bucket_delete` on a bucket containing an object fails with `ErrorCode.CONFLICT` (`BucketNotEmpty`) on all four providers (including Azure), and calling `bucket_delete` on an already-deleted bucket returns `false` without error.
3. **`03-object-crud-text-and-unicode`** — Putting a UTF-8 object with quotes, newlines, and multi-byte Unicode (`雪 / 🚀`) round-trips byte-for-byte via `object_get`, reports accurate byte length via `object_head`, and after `object_delete` leaves `object_head(...).exists() == false` and `object_get` failing with `ErrorCode.NOT_FOUND`.
4. **`04-object-binary-and-empty-roundtrip`** — Putting both a zero-byte payload (`""`) and a raw binary payload containing NUL (`\x00`) and non-UTF-8 bytes (`\xff\xfe`) preserves exact byte length (`size()`) and exact `str_hex_encode(object_get(...))` across all four providers.
5. **`05-object-overwrite-and-etag`** — Overwriting an existing key via `object_put` atomically replaces the body and `size()`, returns a non-empty normalized `etag()` (without surrounding quotes), and updates the ETag when the payload changes.
6. **`06-object-metadata-and-content-type`** — Uploading an object with explicit `content_type` (`"application/json"`) and custom `StrMap` metadata (`str_map().set("env", "staging").set("build_id", "42")`) returns matching `content_type()` and normalized lowercase metadata entries via `object_head` with provider header prefixes (`x-amz-meta-`, `x-ms-meta-`, `opc-meta-`) stripped.
7. **`07-object-list-prefix-and-order`** — Seeding hierarchical keys (`logs/2026/a.txt`, `logs/2026/b.txt`, `logs/2025/c.txt`, `root.txt`) and calling `object_list` with prefix `"logs/2026/"` and `""` returns only matching keys in deterministic ascending UTF-8 byte order with accurate `size()` and `etag()` on each `ObjectSummary`.
8. **`08-object-list-pagination`** — Seeding 5 objects under a common prefix and paging with `object_list(bucket, prefix, 2, token)` until `!page.has_more()` visits all 5 keys in lexicographical order across 3 pages (`2 + 2 + 1`) with zero duplicates or gaps.
9. **`09-delete-missing-idempotency`** — Calling `object_delete` on a non-existent key inside an existing bucket (and calling `object_delete` a second time after deleting a real object) succeeds idempotently with `ErrorCode.OK` on all four providers without raising `NOT_FOUND`.
10. **`10-not-found-errors`** — Calling `object_get`, `object_head`, `object_delete`, or `object_list` on a non-existent bucket fails with `ErrorCode.NOT_FOUND`, whereas `bucket_exists` on a missing bucket and `object_head` on a missing key in an existing bucket return `false` / `exists() == false` with `ErrorCode.OK`.
11. **`11-validation-guards`** — Passing non-portable bucket names (`"Bad_Bucket"`, `"a--b"`, `"ab"`), invalid object keys (`"/leading"`, `"a//b"`, `"../escape"`), or invalid metadata keys (`"bad-hyphen"`, `"1digit"`) fails pre-flight with `ErrorCode.INVALID_ARGUMENT` (`http_status() == 0`) before any network call.
12. **`12-auth-enforced-denial`** — Against `<provider>sim --auth enforce`, requests with missing/bad credentials fail with `ErrorCode.UNAUTHENTICATED` and IAM/RBAC-denied actions fail with `ErrorCode.PERMISSION_DENIED`, never masquerading as `bucket_exists == false` or `ObjectMeta.exists() == false`.
