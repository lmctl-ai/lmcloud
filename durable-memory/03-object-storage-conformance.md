# 03 — Object Storage Conformance Scenarios (`lmcloud`)

Each conformance scenario below is implemented as a standalone `lmscript` program under `tests/conformance/object-storage/NN-<scenario>.lms` and executed via `tests/run-conformance.sh <host-binary> [endpoint] [run-id]`.
- Simulators are driven exclusively by `lmscript` through the `lm<provider>` host (`run_lmcode(program, {command:[ARGV[0], "--lmcode", "$DSLFILE"]})`), never via `curl` or direct HTTP clients.
- Every scenario embeds a per-run unique suffix (`run_id` from `ARGV[2]`, generated randomly by `tests/run-conformance.sh`) into its bucket names (`lmcloud-cNN-<run_id>-...`) so live cloud runs avoid global bucket-name collisions and rapid Azure runs avoid `409 ContainerBeingDeleted` (~30s cooldown) (L2).

> **Execution status:** All 12 `.lms` conformance programs pass static type and bytecode compilation checks (`lmscript --check`) against `schema/lmcloud.dsl.json`. They cannot be executed at runtime yet because the four Go hosts (`lmaws`, `lmazure`, `lmgcp`, `lmoci` on `lmctl-ai/lmcode-go`) have not been implemented yet.

## Scenarios

1. **`01-bucket-lifecycle`** (`tests/conformance/object-storage/01-bucket-lifecycle.lms`) — Creating new buckets with a unique per-run suffix returns `true`, makes `bucket_exists` return `true` and includes the buckets in `bucket_list` (which follows all pages) in ascending lexicographical order, and deleting the empty buckets returns `true` and makes `bucket_exists` return `false`.
2. **`02-bucket-idempotency-and-nonempty-guard`** (`tests/conformance/object-storage/02-bucket-idempotency-and-nonempty-guard.lms`) — Calling `bucket_create` on an existing caller-owned bucket returns `false` without error (including on S3 `us-east-1` via `HEAD`-before-`PUT`, H3), calling `bucket_delete` on a bucket containing an object fails with `ErrorCode.CONFLICT` (`BucketNotEmpty`) on all four providers (including Azure), and calling `bucket_delete` on an already-deleted bucket returns `false` without error.
3. **`03-object-crud-text-and-unicode`** (`tests/conformance/object-storage/03-object-crud-text-and-unicode.lms`) — Putting UTF-8 objects with quotes, newlines, and multi-byte Unicode (`雪 / 🚀`) under both standard hierarchical keys and keys containing special characters (space ` `, `+`, `%`, `?`, `#`, and Unicode `雪`, M6) round-trips byte-for-byte via `object_get`, reports accurate byte length via `object_head`, and after `object_delete` (void, M8) leaves `object_head(...).exists() == false` and `object_get` failing with `ErrorCode.NOT_FOUND`.
4. **`04-object-binary-and-empty-roundtrip`** (`tests/conformance/object-storage/04-object-binary-and-empty-roundtrip.lms`) — Putting both a zero-byte payload (`""`) and a raw binary payload constructed via `str_hex_decode("00fffe41007f80810a")` containing NUL (`\x00`) and non-UTF-8 bytes (`\xff\xfe`) preserves exact byte length (`size()`) and exact `str_hex_encode(object_get(...))` across all four providers (L6).
5. **`05-object-overwrite-and-etag`** (`tests/conformance/object-storage/05-object-overwrite-and-etag.lms`) — Overwriting an existing key via `object_put` atomically replaces the body and `size()`, returns a non-empty opaque `etag()` (with surrounding quotes stripped), and changes the ETag within the same provider when the payload changes (L4).
6. **`06-object-metadata-and-content-type`** (`tests/conformance/object-storage/06-object-metadata-and-content-type.lms`) — Uploading an object with explicit `content_type` (`"application/json"`) and custom `StrMap` metadata (`str_map().set("env", "staging").set("build_id", "42")`) returns matching `content_type()` and normalized lowercase metadata entries via `object_head` with provider header prefixes (`x-amz-meta-`, `x-ms-meta-`, `opc-meta-`) stripped.
7. **`07-object-list-prefix-and-order`** (`tests/conformance/object-storage/07-object-list-prefix-and-order.lms`) — Seeding hierarchical keys (`logs/2026/a.txt`, `logs/2026/b.txt`, `logs/2025/c.txt`, `root.txt`) and listing with prefix `"logs/2026/"` and `""` — following `next_token()` until `!has_more()`, since a provider may return short pages (M7) — returns only matching keys in deterministic ascending UTF-8 byte order with accurate `size()` and non-empty `etag()` on each `ObjectSummary`.
8. **`08-object-list-pagination`** (`tests/conformance/object-storage/08-object-list-pagination.lms`) — Seeding 5 objects under a common prefix, paging with `object_list(bucket, prefix, 2, token)` until `!page.has_more()`, and calling `object_list_all(bucket, prefix)` both return all 5 keys in ascending lexicographical UTF-8 byte order with zero duplicates and zero gaps without assuming a fixed per-page split (M7, L3).
9. **`09-delete-missing-idempotency`** (`tests/conformance/object-storage/09-delete-missing-idempotency.lms`) — Calling `object_delete` (`void`, M8) on a non-existent key inside an existing bucket and calling `object_delete` a second time after deleting a real object both succeed idempotently with `ErrorCode.OK` on all four providers without raising `NOT_FOUND`.
10. **`10-not-found-errors`** (`tests/conformance/object-storage/10-not-found-errors.lms`) — Calling `object_get`, `object_head`, `object_delete`, `object_list`, or `object_list_all` on a non-existent bucket fails with `ErrorCode.NOT_FOUND` (and aborts with `[NOT_FOUND]` in default mode, L5), whereas `bucket_exists` on a missing bucket and `object_head` on a missing key in an existing bucket return `false` / `exists() == false` with `ErrorCode.OK`.
11. **`11-validation-guards`** (`tests/conformance/object-storage/11-validation-guards.lms`) — Passing non-portable bucket names (`"Bad_Bucket"`, `"a--b"`, `"ab"`, S3-reserved `"sthree-test"` / `"bad-s3alias"` / `"amzn-s3-demo-x"`, GCS-reserved `"goog-test"` / `"my-google-bucket"`, L1), Azure-unsafe or invalid object keys (`"/leading"`, `"a//b"`, `"../escape"`, `"trailing."`, `"seg./file"`, `"back\\slash"`, M6), invalid `content_type` (`""`, `"text/plain\r\n"`, `"no-slash"`, M5), invalid metadata keys (`"bad-hyphen"`, `"1digit"`), out-of-range `max_keys` (`1001`), unknown service or non-loopback `http://` in `set_endpoint` (M2, M4) fails pre-flight with `ErrorCode.INVALID_ARGUMENT` (`http_status() == 0`) before any network call.
12. **`12-auth-enforced-denial`** (`tests/conformance/object-storage/12-auth-enforced-denial.lms`) — Runs **only** against `<provider>sim --auth enforce` (emits a TAP `# SKIP` when the simulator is in open auth mode, M6; **OCI portion is sim-only**, H1). Executes two distinct passes: (a) an unauthenticated pass (wrong secret/token) asserting `ErrorCode.UNAUTHENTICATED` on body-bearing operations (`bucket_create`, `object_put`), and (b) a policy-denied pass (authenticated restricted principal) asserting `ErrorCode.PERMISSION_DENIED` on both body-bearing operations and `bucket_exists` / `object_head` probes (never `exists == false` with `ErrorCode.OK`; S3 `HEAD` exception documented per H2 where `403` without body always maps to `PERMISSION_DENIED`).

## Sim enhancements

Inspection of `/home/ubuntu/cloud/{awssim,azuresim,gcpsim,ocisim}` source overlays, docs, and test suites identified the following concrete simulator gaps/quirks relevant to the 12 conformance scenarios:

1. **`awssim` — `src/main/java/ai/lmctl/awssim/AuthFilter.java` (lines 37–38, 66–77, 115–118, 130–134) & `scripts/test-auth.py`:**
   - **What is missing/wrong:**
     - `SUPPORTED.get("s3")` (lines 37–38) lists `"ListAllMyBuckets"`, `"CreateBucket"`, `"DeleteBucket"`, `"ListBucket"`, `"GetBucketLocation"`, `"PutBucketTagging"`, `"GetBucketTagging"`, `"DeleteBucketTagging"`, `"PutObject"`, `"GetObject"`, `"DeleteObject"`, omitting `"HeadBucket"` and `"HeadObject"` if upstream `IamActionRegistry.resolveRoute("s3", ctx)` resolves `HEAD /{bucket}` or `HEAD /{bucket}/{key}` to distinct action names (and `scripts/test-auth.py` only tests `PUT` in `--auth enforce` mode, never `HEAD`).
     - In `AuthFilter.java` line 69 (`!rawPath.equals(ctx.getUriInfo().getRequestUri().getRawPath())`), percent-encoded special characters in object keys (`+`, `%25`, `%3F`, `%23` from Scenario 03, M6) must preserve identical raw path representation between Vert.x `request().path()` and JAX-RS `getRequestUri().getRawPath()`.
     - S3 `HEAD` responses strip the XML entity body on the wire (H2), so `403` on `HEAD` maps to `PERMISSION_DENIED` while `UNAUTHENTICATED` vs `PERMISSION_DENIED` classification in Scenario 12 uses body-bearing operations.
2. **`azuresim` — `src/main/java/ai/lmctl/azuresim/StorageAuth.java` (lines 152–160, 217–220) & `scripts/test-storage.py`:**
   - **What is missing/wrong:**
     - In `StorageAuth.java` line 219 (`raw.toLowerCase(Locale.ROOT).matches(".*%(2f|5c|25).*") || path.contains("\\") || path.contains(";")`), `--auth enforce` mode rejects `%25` (percent-encoded `%`) and `;` in blob paths, blocking keys containing literal `%` (Scenario 03, M6) when `--auth enforce` is active; `StorageAuth.target` should only reject encoded path separators (`%2f`, `%5c`) and dot-segments, not `%25` in blob names.
     - `scripts/test-storage.py` verifies basic container/blob CRUD and `prefix` filtering (lines 29–39), but never tests `maxresults` + `marker` -> `<NextMarker>` pagination (`08-object-list-pagination`) or `x-ms-meta-*` custom metadata headers on `HEAD` in open mode.
     - Upstream `floci-az` `DELETE /{account}/{container}?restype=container` deletes non-empty containers without returning `409 Conflict` (handled by `lmazure`'s pre-flight `maxresults=1` check per Decision 3, or optionally enforced in `azuresim`).
3. **`gcpsim` — `src/main/java/ai/lmctl/gcpsim/PermissionFilter.java` (lines 73–98) & `scripts/test-lifecycle.py` (lines 53–68):**
   - **What is missing/wrong:**
     - In `scripts/test-lifecycle.py` (lines 53–59), setting custom `metadata` and `contentType` uses a 2-step `POST /upload/storage/v1/b/{b}/o?uploadType=media` + `PATCH /storage/v1/b/{b}/o/{k}` because single-request `uploadType=multipart` with binary payloads + JSON `metadata`/`contentType` is only tested for auth rejection in `scripts/test-auth.py` (lines 109–112). In `--auth enforce` mode, a 2-step `POST` + `PATCH` requires both `storage.objects.create` (line 94) and `storage.objects.update` (line 97); `gcpsim` should verify/support single-request `uploadType=multipart` preserving raw binary bytes alongside JSON `metadata` and `contentType`.
     - `scripts/test-lifecycle.py` (line 64) only tests unpaginated `prefix=dir/` listing and never verifies `maxResults` + `pageToken` -> `nextPageToken` pagination (`08-object-list-pagination`) or `409` on deleting a non-empty bucket (`02-bucket-idempotency-and-nonempty-guard`).
4. **`ocisim` — `src/main/java/ai/lmctl/ocisim/OciAuthFilter.java` (lines 205–219) & `scripts/test-integration.py` (lines 207–276):**
   - **What is missing/wrong:**
     - `OciAuthFilter.reject()` (lines 213–219) returns HTTP `403` with JSON `"code": "NotAuthorizedOrNotFound"` in `--auth enforce` mode (whereas live OCI returns HTTP `404` with `"code": "NotAuthorizedOrNotFound"` when the caller lacks `inspect` permission, H1), and writes the error code only in the JSON response body without setting an HTTP header for `HEAD` requests.
     - `scripts/test-integration.py` (lines 234–245) tests basic `PutObject`/`HeadObject`/`GetObject`/`ListObjects`/`DeleteObject`, but never tests `opc-meta-*` custom metadata preservation on `PutObject`/`HeadObject` (`06-object-metadata-and-content-type`) or `limit` + `start` -> `nextStartWith` pagination on `ListObjects` (`08-object-list-pagination`).
